# Repository contribution requirements

- Read README, PROGRESS, DEVELOPMENT_PLAN and the latest main before editing. Preserve concurrent changes; never overwrite a newer tree or force-push main.
- Keep public contributions limited to code, redistributable data, source/license evidence, technical design, reproducible validation and contributor-facing change records. Private conversations, credentials, account authorization, usage limits, personal project material and transient coordination state do not belong in this repository.
- Treat .gitignore as a convenience, not an access control. Inspect an explicit list of files and their contents before any API, plugin or Git upload.
- Retain stable IDs, source attribution, per-entry licenses, jurisdiction evidence and field-level review status. Classification review must not imply expert translation review.
- Validate data and run relevant tests. Do not report an unexecuted check as passed. Check both CI results and actual published artifacts.
- Record technical changes, validation results and remaining product gaps in README, PROGRESS and WORK_LOG. Keep private operational notes outside the repository.
- For parallel contributions, use separate branches and review changes before integrating them into main.
