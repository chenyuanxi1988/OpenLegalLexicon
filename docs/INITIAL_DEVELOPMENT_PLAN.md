# OpenLegalLexicon 开发计划

本计划描述从项目框架到首个可复用版本的开发顺序。初始内容包括 MIT 许可证、README 与本文档；数据和工具尚未实现。里程碑以验收条件推进，不预设未经确认的交付日期。

## 目标与首版边界

首版目标是建立可维护的中英文法律语音资源结构，提供可追溯的少量公共数据、一个经过验证的引擎适配器和可复现的评测方法。

第一阶段先完成结构和规范，不以词条数量为目标。首版不训练 ASR 基础模型，不建立完整法律知识库，也不上传客户、项目或非公开案件词表。

- [ ] 调查中文法律词表、法律双语资源、ASR 热词项目和输入法词库；记录可借鉴的设计与使用边界。
- [ ] 对候选来源逐项核实数据许可，不能仅根据仓库代码许可证推断数据许可。
- [ ] 选取一个业务领域和明确法域，制作可人工逐条审核的最小数据包。
- [ ] 记录双语对应、读音、法域及适用范围的审核依据。
- [ ] 建立核心词、机构名称和法规名称的不同更新策略。

**验收条件：** 发布候选条目全部通过结构校验；来源和再分发状态可追溯；同形异义未被误合并；公共数据中不含私有业务信息。数量目标在审核成本和数据质量明确后制定。

## M3：校验、构建与发布产物

- [ ] 实现结构、重复项、跨文件引用、许可状态和审核状态校验。
- [ ] 支持按语言、业务领域、法域和词条状态筛选。
- [ ] 合并词包并输出冲突报告，不因文字相同就丢弃不同法域概念。
- [ ] 导出 JSONL、TSV 和通用纯文本词表，统一编码、排序和换行。
- [ ] 为导出结果附带来源与署名文件、数据版本、构建配置和校验和。

**验收条件：** 相同版本与配置产生相同内容；未审核或许可未确认的数据无法进入正式发布；每个导出条目可以追溯到源条目；引擎不支持的元数据仍在配套清单中保留。

## M4：首个语音识别适配器

- [ ] 优先核验待适配的 Qwen3-ASR 版本、接口与限制。
- [ ] 根据实际接口确定使用上下文提示、热词参数或其他机制。
- [ ] 实现候选筛选、数量或长度预算、稳定排序与去重。
- [ ] 明确是否支持权重及其数值范围；无对应机制时不伪造通用权重。
- [ ] 在本地完成公共、个人和当前任务词表叠加；不把私有词表写回公共构建产物。

**验收条件：** 完成真实接口调用验证；空词库、超出预算和冲突词条行为明确；同一音频可以复现无词库及启用词库两组输出。通过后再考虑 Whisper、FunASR 与输入法适配。

## M5：基线与回归评测

### 样本设计

- 中文法律口述、英文术语、缩写与中英混合表达。
- 不同法域、机构名称、法规名称、法条和数字格式。
- 同音或近音词、真实别名、容易触发错误替换的普通句子。
- 不包含目标热词的负样本，以及背景噪声和语速变化样本。

语料优先采用原创脚本与获得公开发布授权的录音；记录文本和音频各自的来源与许可。按说话人及内容划分开发集和测试集，避免近似录音跨集合泄漏。

### 实验与指标

| 对照组或指标 | 用途 |
| --- | --- |
| 无词库基线 | 测量模型原始识别表现 |
| 核心库 / 核心加领域包 / 按语境选择 | 比较加载策略与词表规模 |
| 中文 CER、英文 WER | 评估语言层面的识别错误 |
| 术语 precision、recall、F1 | 同时衡量正确检出、遗漏和误报 |
| 法律实体错误率 | 单独观察机构、法规等关键信息 |
| 误替换率与负样本回归 | 检查过度偏置和后处理带来的损害 |
| 时延、内存及运行配置 | 评估本地输入场景的可用性 |

在评测规范中明确每个指标的分母、匹配粒度、分词方法、大小写及标点处理；公开样本数与分组结果。规范化前后分别评分，避免把格式调整当作 ASR 识别提升。

**验收条件：** 第三方能按记录复现实验；改善与回归均被报告。获得基线后，在调参前确定回归容忍范围和发布阈值，再用保留测试集验收，不能根据最终测试结果事后修改门槛。

## 维护与贡献流程

1. 提交问题、来源或变更动机，并提供最小示例。
2. 核验法域、双语关系、来源许可和公开范围。
3. 修改结构化源数据，运行相关校验与必要的回归评测。
4. 由维护者审核后合入，生成新版本与变更记录。

涉及混淆纠正或权重调整的贡献，应附模型版本、触发样本和不应触发的反例。涉及法规与机构变动时保留历史记录；涉及来源撤回时同步检查已发布产物及署名文件。
